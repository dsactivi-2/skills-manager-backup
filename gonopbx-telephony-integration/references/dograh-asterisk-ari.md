# Dograh Asterisk ARI Reference

## What Dograh needs from Asterisk

Dograh connects to Asterisk through the Asterisk REST Interface (ARI). The retrieved Dograh page describes ARI as a WebSocket-based event model for controlling calls through Stasis applications and external media streaming.

Prerequisites from the source:

- A running Asterisk instance.
- ARI enabled.
- `chan_websocket` available and loaded.
- `res_websocket_client` available and loaded.
- Network connectivity between Dograh and Asterisk.
- A running Dograh instance.

Do not assume these modules exist in GOno PBX. Verify inside the deployed Asterisk environment before promising compatibility.

## Asterisk configuration concepts

Dograh's source references these Asterisk files:

- `ari.conf`: enable ARI and define the ARI user/password.
- `http.conf`: enable the Asterisk HTTP server and expose the ARI HTTP endpoint.
- `extensions.conf`: route target extensions into `Stasis(<app-name>)`.
- `websocket_client.conf`: define the media WebSocket client connection to Dograh.

The Dograh cloud WebSocket path in the source uses `wss://api.dograh.com/api/v1/telephony/ws/ari`. Self-hosted Dograh can use the corresponding host and scheme for that deployment.

## Dograh configuration fields

The Dograh ARI configuration needs:

- ARI endpoint URL: the HTTP base URL of the Asterisk ARI server.
- Stasis app name: matches the ARI user/app name used in Asterisk.
- App password: matches the ARI password.
- WebSocket client name: matches the section name in `websocket_client.conf`.
- From extensions: optional SIP extensions or trunk numbers for outbound calls.

## Inbound call behavior

Dograh does not use ordinary provider webhooks for Asterisk inbound calls. Asterisk routes the call into Stasis, ARI emits the event, and Dograh selects the workflow assigned to the called extension in its telephony configuration.

For every extension that should reach a Dograh workflow:

1. Ensure the Asterisk dialplan routes the called extension into the Stasis app.
2. Add the extension as a phone number in Dograh's Asterisk ARI configuration.
3. Assign the intended inbound workflow in Dograh.
4. Test a call to that extension.

## Codec rule

Keep G.711 mu-law (`ulaw`/PCMU) available for call paths involving Dograh, because the retrieved source states Dograh's external media channel uses G.711 mu-law.

## Security rules

- Use strong ARI credentials.
- Restrict ARI network access to known Dograh/self-hosted sources.
- Do not expose ARI broadly without firewall controls.
- Do not print ARI or Dograh secrets in reports.

## GOno PBX-specific caution

GOno PBX documentation describes generated PJSIP and dialplan configuration, but the retrieved GOno PBX sources do not document ARI as a managed UI feature. Treat Dograh configuration as an Asterisk-level extension to GOno PBX and verify persistence before editing generated files.

## Persistence planning for GOno PBX deployments

Before changing ARI, HTTP, WebSocket, or Stasis dialplan behavior, identify whether the target file is generated by GOno PBX or maintained as a persistent custom file. Do not edit generated files as the final source of truth because later UI/API changes may overwrite them.

Use this decision path:

1. Inspect the deployed compose/volume layout and find the persistent Asterisk config volume.
2. Identify whether `ari.conf`, `http.conf`, `extensions.conf`, and `websocket_client.conf` are managed directly, templated, or generated by GOno PBX.
3. If GOno PBX has a supported custom include mechanism, prefer that path for Stasis and ARI-related additions.
4. If no include mechanism is documented in the deployment, stop and ask the user to approve a persistence strategy before edits.
5. After any approved change, verify that restarting/recreating the Asterisk container preserves the intended config before calling it production-ready.

The bundled preflight script can check module and ARI visibility, but it does not prove persistence. Persistence requires deployment-specific inspection and an approved restart/recreate test plan.

## Runtime values to request
