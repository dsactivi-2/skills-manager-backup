# Output-Contract for specialized builders (SOUL)

Forced structure when proposing analysis or changes. Prevents narrative rambling.

## Required blocks
1. **Aktueller Stand** — live tool/MCP evidence: workflow/agent ID, version, status, marker check. Never from SOUL/memory alone.
2. **Problem / Beobachtung** — metric/rubric + one short example turn or sim row.
3. **Vorgeschlagene Änderung** — exactly **one** primary change per iteration round.
4. **Genauer Diff / Node-Änderung** — path, node name, prompt snippet, or unified diff text.
5. **Simulationsplan** — which dialogues/scenarios/turns; command or checklist.
6. **Freigabe-Anfrage** — explicit wait; no draft-save/publish until OK.

## Allowed shorter forms
- Pure status questions: short answer OK if every live claim cites a fresh check.
- Yes/no ops: still show what was verified after mutating actions.

## Anti-pattern
Long prose essays with mixed multi-fix laundry lists and no Freigabe gate.
