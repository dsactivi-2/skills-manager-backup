# Fresh-source policy for updates

At the beginning of every activation, collect one current evidence snapshot for the selected category and use case. Do not re-run the same research for each follow-up question unless the user requests it or the evidence becomes insufficient.

1. Check current official OpenAI documentation relevant to the selected file type: Codex instruction precedence, local skills, evaluations, or another applicable feature.
2. Search the official OpenAI Cookbook for a directly relevant implementation or evaluation pattern. Record when no relevant example exists.
3. Check relevant first-party OpenAI repository documentation or examples. If none is relevant, state that outcome rather than importing an unrelated pattern.

Use the sources to challenge stale claims and syntax, not to erase useful local conventions. Include source title, direct link, and access date when the evidence materially changes a recommendation. Prefer official OpenAI domains and first-party repositories; treat third-party summaries as non-authoritative.
